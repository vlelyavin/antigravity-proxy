# antigravity-proxy

[English README](README.md)

у тебя есть подписка google ai pro. твоим инструментам нужен openai-эндпоинт. посередине стоит это: локальный релей, который прогоняет openai chat-completions через oauth антигрэвити / code assist — hermes, opencode и всё openai-совместимое ездят на подписке вместо поминутного билла.

## что делает

- читает локальный oauth-токен antigravity/gemini с диска на каждый запрос — свежий логин где-то ещё подхватывается без рестарта
- переводит openai `chat/completions` ↔ cloud code `generateContent` структурно, в обе стороны, включая tool calls и картинки
- стримит: openai SSE из cloud-code SSE-кадров
- мультиаккаунт sticky-first: первый здоровый аккаунт обслуживает запросы, остальные подхватывают при сбое
- ретраит 5xx/сеть с бэкоффом; квотные ошибки не валят запрос, а переключают аккаунт
- опциональный api key, чтобы порт не был бесплатным для всей локалки
- ноль зависимостей. только stdlib node.

## чем не является

- не продукт google, никак с ними не связан
- не хостед-сервис — работает на твоей машине, твои креды
- не бандл кредов — в репо ничего приватного нет

## честно

использует подписочный oauth вне официального клиента. серая зона tos google — тот же клуб, что у всех code-assist прокси. выжмёшь — можно потерять подписку; квота пер-юзер (~1500 запросов/день на ai pro), и один агентный промпт жжёт несколько запросов. твоё решение.

## требования

- node 20+ (без сборки, без npm install)
- локальный oauth-токен из одного из:
  - **antigravity cli** (`agy`) → `~/.gemini/antigravity-cli/antigravity-oauth-token`
  - **gemini cli** (`npm i -g @google/gemini-cli && gemini`) → `~/.gemini/oauth_creds.json`
  - любой файл с `{access_token, refresh_token, project_id?}` в `~/.antigravity-proxy/accounts/*.json`

## запуск

```bash
git clone https://github.com/vlelyavin/antigravity-proxy.git
cd antigravity-proxy
node src/cli.js
```

слушает `127.0.0.1:8317`.

```bash
curl -sS http://127.0.0.1:8317/health
```

health показывает все найденные аккаунты и срок токена. дальше:

```bash
curl -sS http://127.0.0.1:8317/v1/chat/completions \
  -H 'content-type: application/json' \
  --data '{"model":"gemini-3.8-flash-high","messages":[{"role":"user","content":"reply with exactly: pong"}]}'
```

`pong` — весь путь работает.

## мультиаккаунт

доложи дополнительные токен-файлы в `~/.antigravity-proxy/accounts/*.json` (формат: `{access_token, refresh_token, project_id?, email?}`). выбор sticky-first: первый подходящий аккаунт в порядке файлов обслуживает запросы, сохраняя его prompt cache; остальные - запас. 2-3 аккаунта на один резидентский exit ip - разумный потолок.

два вида состояния не смешиваются:

- **локальное для запроса**: какие аккаунты этот запрос уже пробовал. оно никогда не меняет общее здоровье пула.
- **общее и узкое**: доказанное ограничение ровно одного аккаунта, пары аккаунт+модель, проектного ресурса или egress. неизвестная ошибка никогда не расширяется до состояния всего аккаунта.

политика отказов:

| наблюдение | действие в запросе | общее состояние |
|---|---|---|
| отмена клиентом или общий deadline | стоп, новой работы нет | нет |
| неверный вход/конфиг, локальный сбой разбора | стоп с явной причиной | нет |
| отказ или документированный терминал (`STOP`, `MAX_TOKENS`, safety) | вернуть как есть | нет |
| truncated/malformed/неизвестный терминал | ограниченная альтернатива | нет |
| generic 5xx, неизвестный сетевой/body-сбой | ограниченная альтернатива | нет |
| голый 429 / `RESOURCE_EXHAUSTED` без scoped-доказательства | альтернатива только внутри запроса | нет: владелец квоты неизвестен |
| generation 401 / `UNAUTHENTICATED` | один refresh и максимум один повтор этой креды; второй 401 - локальный обход `auth_rejected_after_refresh` | нет |
| точный структурированный `invalid_grant` token-endpoint | альтернатива | это поколение материал-креды блокируется до смены refresh token или ручного retry оператора |
| OAuth timeout/429/5xx/malformed | ограниченная альтернатива с классом сбоя refresh | нет |
| доказанный сбой egress dial/CONNECT | альтернатива на другом закреплённом egress | только этот egress; direct-фолбэка нет |
| неоднозначный 403/permission/model | ограниченная альтернатива или явный отказ | нет |

только проверенный scoped-сигнал квоты провайдера может охладить аккаунт/модель/проект. настоящих AGY quota-метаданных пока не установлено: ветка scoped quota - это словарь контракта, и удобные поля в фикстуре её не активируют.

неизвестные, протокольные и transient-сбои делят один локальный бюджет в **две** неудачные попытки. для N кред, загруженных на входе запроса, разрешено не больше **2N generation POST**, **2N OAuth POST** и **N project POST**; одной креда достаётся максимум два generation POST, и соединенческий retry делит этот лимит с forced-auth retry. присоединение к уже идущему общему refresh считается join, а не ещё одним POST. общий deadline всегда главнее.

истёкшее ограничение допускает ровно одну реальную попытку как recovery probe. lease держится всё время этой попытки и снимается при успехе, ошибке, отмене и таймауте; истечение или release - не recovery. успешный probe очищает только состояние, чья ревизия доказательств не изменилась: поздний успех не стирает более новое охлаждение. поздний сбой старого поколения креды не отключает заменённую, а обычный refresh access token - это новая версия токена, не замена материала. выведенная доступность живёт в процессе: рестарт пишет `pool.reset` и очищает её - это явный сброс, а не подтверждённое восстановление.

у каждого запроса один общий бюджет, `rotation.requestDeadlineMs` (по умолчанию 110 с): подготовка, все попытки по аккаунтам, сборка стрима и vertex-фолбэк делят его, и ни один кадр или ретрай его не сбрасывает. исчерпанный бюджет отвечает 504 и не штрафует аккаунты.

клиент, который не готов ждать зависший upstream, присылает `x-attempt-timeouts-ms: 45000,30000` (только non-stream): первая попытка получает min(45 с, остаток бюджета), следующая - min(30 с, остаток, последнее значение повторяется), затем отвечает vertex-фолбэк. без заголовка есть только общий бюджет.

два таймера режут попытку, которая держит сокет без прогресса: `rotation.firstMeaningfulFrameTimeoutMs` (45 с) ждёт первый осмысленный кадр с начала попытки, включая подготовку, `rotation.idleTimeoutMs` (30 с) ограничивает паузу между осмысленными кадрами. осмысленный кадр - текст, thinking, вызов инструмента или подпись, отказ или явный терминал; keepalive и кадры только с ролью не сбрасывают таймеры. до записи клиенту срез переключает на следующий аккаунт; после старта клиентского стрима тот же срез закрывает стрим ошибкой, чужой вывод в него не попадает. уже открытый стрим всё равно классифицирует независимо доказанное состояние здоровья, но не ретраится.

ответ считается успешным только с документированной причиной завершения (`STOP` -> `stop`, `MAX_TOKENS` -> `length`, safety -> `content_filter`) или отказом на уровне промпта. `MALFORMED_FUNCTION_CALL`, `LANGUAGE`, `OTHER`, unspecified, некорректный тип и неизвестная причина - это 502, а не поддельный `stop`; стрим без терминального кадра тоже. нативный буферный `generateContent` применяет те же проверки явной ошибки и терминала (встроенный 429 или candidate без терминала не становятся 200), а `promptFeedback`-отказ остаётся корректным успешным исходом. подписи инструментов и отказы проходят без изменений.

исчерпание пула описывает фактические причины: 429 возвращается, только если доказанная квота объясняет все исключения; все заблокированные креды или egress-gate дают 503, смешанная/неизвестная история - явный 503 или последнюю реальную ошибку, а не выдуманный 429. `Retry-After` берётся только из записанного времени доступности или реального заголовка upstream, не из локальной константы.

`GET /health` сохраняет прежние поля и добавляет `liveness` (читаются ли креды) и `eligibility` (scoped-ограничения, срок, безопасная причина, активные recovery probe, только псевдонимы). читаемые креды не равны доступности.

## журнал и корреляция

один строгий UUID идентифицирует один входящий вызов. `x-request-id` клиента принимается только в форме корректного UUID; произвольный текст заменяется сгенерированным UUID и не попадает в журнал. каждый ответ - успех, ошибка, native и SSE - несёт `x-agy-request-id`, `x-agy-route` (`agy` или `vertex_fallback`), `x-agy-attempts` (число попыток по аккаунтам), `x-agy-policy` (`agy-rotator-1`) и, для ошибки, фиксированный `x-agy-reason`. на стриме число попыток - известное на момент отправки заголовков.

журнал без payload: ни текста промпта или ответа, ни тела апстрима, ни текста отказа, ни токенов, email, путей к кредам и id проекта. аккаунты - `acct-` плюс восемь hex от sha256 пути, egress - `egress-<hash>`, проектный ресурс - `project-<hash>`. `attempt.start`/`attempt.timing` несут индекс попытки, наблюдаемый статус, структурированную причину/фазу/scope/evidence, решение политики, эффект общего состояния, retry/stop reason, раздельные `modelRequested`/`modelOutbound`/`modelReported` и счётчики POST. `request.timing` несёт итог, бюджеты и фактические counts исчерпания. `pool.restriction`/`pool.recovered` фиксируют каждое доказанное изменение и восстановление. подробный список полей - в английском README, раздел journal and correlation.

## структура

```
src/
  config/         дефолты, env-оверрайды, лоадер
  credentials/    поиск токен-файлов (agy / gemini-cli / raw), oauth refresh
  rewrite/        openai <-> cloud code трансформы + каталог моделей
  upstream/       клиент cloud code, структурированные отказы/политика, scoped-пул
  server/         http: /health, /v1/models, /v1/chat/completions
test/             node:test, без сети (один локальный cert-фикстур)
```

## безопасность

- только localhost, если точно не знаешь, зачем иначе
- никогда не коммить токен-файлы и config.json
- поставь `apiKey` в config.json, если к порту может достучаться не только твоя машина

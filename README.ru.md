# antigravity-proxy

[English README](README.md)

Если у вас есть подписка Google AI Pro, а рабочим инструментам нужен OpenAI-совместимый эндпоинт, этот проект решает задачу. Локальный релей транслирует запросы OpenAI chat completions через OAuth от Antigravity / Code Assist, позволяя Hermes, OpenCode и любым другим совместимым клиентам работать по подписке вместо поминутной оплаты API.

## Что делает

- Перечитывает локальный OAuth-токен Antigravity/Gemini с диска на каждый запрос: свежая авторизация подхватывается без перезапуска.
- Структурно транслирует OpenAI `chat/completions` ↔ Cloud Code `generateContent` в обе стороны, включая вызовы инструментов и изображения.
- Стримит: OpenAI SSE из кадров Cloud Code, а нативный `:streamGenerateContent` отдаёт кадры апстрима как есть.
- Вычищает маркеры харнесса из system instruction (`Nous Research`, `Hermes`, `Claude Code`, `Anthropic` и другие) перед отправкой: Cloud Code отвечает непрозрачным 429 на некоторые из них.
- Структурная квота: ответ с `QuotaFailure` / `QUOTA_EXHAUSTED` или временем сброса в `error.details[]` паркует аккаунт и модель до этого сброса, а не долбит их каждым следующим запросом.
- `403 TOS_VIOLATION` / `UNSUPPORTED_CLIENT` паркует аккаунт до действия оператора, а запрос уходит на следующий; scoped-состояние переживает рестарт.
- Несколько аккаунтов, sticky-first: первый подходящий аккаунт обслуживает серию запросов, остальные - переполнение.
- Ротация по доказательствам: голый 429 переключает внутри запроса и не трогает общее состояние; только точный `invalid_grant` на token endpoint блокирует поколение credential, а доказанный сбой egress гасит лишь этот egress.
- Ограничивает зависший сокет: ждёт первый содержательный кадр и следит за паузами между кадрами.
- Опциональный API-ключ, чтобы порт не был открыт всем в локальной сети.
- Ноль внешних зависимостей: только стандартная библиотека Node.js.

## Чем не является

- Не является продуктом Google и никак с компанией не связан.
- Не хостится вовне: работает исключительно на вашей машине с вашими учётными данными.
- Не распространяет готовые учётные данные: в репозитории нет никаких секретов.

## Честно

Прокси использует подписочный OAuth вне официального клиента. Это серая зона Google ToS, как и у любых других Code Assist прокси; пункт 6 дополнительных условий Antigravity прямо называет сторонние клиенты нарушением. При слишком агрессивном использовании можно потерять подписку. Квота выделяется на пользователя (около 1500 запросов в день на AI Pro), при этом один сложный агентский промпт может генерировать сразу несколько запросов. Используйте на свой страх и риск.

18 ноября 2026 Google убирает Claude Sonnet 4.6, Claude Opus 4.6 и GPT-OSS-120B из Antigravity. Каталог релея уже содержит их замены (Claude 5.5, Gemini 4, Gemini 3 Flash).

## Требования

- Node.js 20+ (без сборки и без `npm install`)
- Локальный OAuth-токен из любого удобного источника:
  - **antigravity cli** (`agy`) → `~/.gemini/antigravity-cli/antigravity-oauth-token`
  - **gemini cli** (`npm i -g @google/gemini-cli && gemini`) → `~/.gemini/oauth_creds.json`
  - Любой JSON-файл вида `{access_token, refresh_token, project_id?}` в каталоге `~/.antigravity-proxy/accounts/*.json`

## Запуск

```bash
git clone https://github.com/vlelyavin/antigravity-proxy.git
cd antigravity-proxy
node src/cli.js
```

Сервер слушает `127.0.0.1:8317`.

```bash
curl -sS http://127.0.0.1:8317/health
```

`/health` покажет все обнаруженные аккаунты и время жизни токенов, а также блок `eligibility` с активными ограничениями пула. Затем:

```bash
curl -sS http://127.0.0.1:8317/v1/chat/completions \
  -H 'content-type: application/json' \
  --data '{"model":"gemini-3.8-flash-high","messages":[{"role":"user","content":"reply with exactly: pong"}]}'
```

Ответ `pong` означает, что цепочка настроена и работает.

Нативная поверхность Gemini и снимок квот:

```bash
curl -sS -X POST http://127.0.0.1:8317/v1beta/models/gemini-3.8-flash:generateContent \
  -H 'content-type: application/json' \
  --data '{"contents":[{"role":"user","parts":[{"text":"reply with exactly: pong"}]}]}'
curl -sS http://127.0.0.1:8317/v1/quota
```

`:streamGenerateContent` по тому же пути отдаёт нативные Gemini SSE-кадры. `/v1/quota` возвращает ответы `retrieveUserQuotaSummary`, собранные при прогреве (`upstream.warmup: true`); это не свежий запрос к апстриму, и в нём только алиасы аккаунтов, без email.

## Подключение к инструментам

Укажите OpenAI-совместимый базовый URL `http://127.0.0.1:8317/v1` и API-ключ (заданный в конфигурации или просто `none`).

Пример для OpenCode:

```jsonc
// ~/.config/opencode/opencode.jsonc
{
  "provider": {
    "antigravity": {
      "npm": "@ai-sdk/openai-compatible",
      "options": { "baseURL": "http://127.0.0.1:8317/v1", "apiKey": "none" },
      "models": {
        "gemini-3.8-flash-high": { "limit": { "context": 1048576, "output": 65536 } },
        "claude-sonnet-5-5-high": { "limit": { "context": 1000000, "output": 128000 } }
      }
    }
  }
}
```

Для Hermes и любых других OpenAI SDK: `base_url=http://127.0.0.1:8317/v1`, `api_key=none`, а идентификаторы моделей - из `GET /v1/models`.

## Модели

21 модель: `gemini-3.8-flash-{low,medium,high,tiered}`, `gemini-4-{argon,hydrogen,carbon}-*`, `gemini-3-flash`, `gemini-3.1-flash-image`, `gemini-3.1/3.5-flash-lite`, `gemini-3.7/3.6-flash-*`, `gemini-3.1-pro-{low,high}`, `claude-sonnet-5-5-high`, `claude-opus-5-5-high`. Каталог лежит в `src/rewrite/models.js`; пополняйте его, когда Google выпускает новые модели.

Доступность зависит от плана аккаунта: Gemini 4 Carbon, 3.7/3.6 Flash и 3.1 Pro - только Enterprise; Gemini 4 Argon и Claude 5.5 требуют платного (не триального) AI Pro или Ultra. Модель в каталоге не гарантирует, что конкретный аккаунт её обслуживает; незнакомый id проверяется одним живым вызовом.

## Мультиаккаунт

Добавьте файлы токенов в `~/.antigravity-proxy/accounts/*.json` (формат: `{access_token, refresh_token, project_id?, email?}`). Выбор sticky-first, не round-robin: первый подходящий аккаунт обслуживает все запросы, остальные - переполнение. Серия запросов на одном аккаунте держит неявный prompt-cache Gemini тёплым, который round-robin делит пополам. 2-3 аккаунта на один резидентский исходящий IP - разумный максимум: больше похоже на ферму, а фермы Google встречает капчей.

Два вида состояния разделены:

- **внутри запроса**: аккаунты, которые уже пробовали в этом запросе; общее здоровье пула не меняется;
- **общее и scoped**: доказанное ограничение ровно на аккаунт, аккаунт+модель, проект или egress. Неизвестный сбой никогда не расширяется до состояния аккаунта.

### Egress: один выход на аккаунт, fail closed

`upstream.egress.accounts` сопоставляет аккаунт (email или имя файла токена вместе с `.json`) его собственному прокси. Правила проверяются на старте и при каждой загрузке credential, а при нарушении аккаунт отклоняется, а не утекает с IP хоста:

- **нет выхода - нет трафика.** Если в развёртывании объявлен хотя бы один выход, аккаунт без своего выхода отклоняется до OAuth, резолва проекта и генерации. Развёртывание без egress - это обычный локальный релей с соединением хоста.
- **один выход - один аккаунт.** Первый аккаунт лейна занимает его; следующий на тот же URL отклоняется, а журнал пишет одну строку `egress.duplicate` с обоими алиасами.
- две авторизованные сессии на одном host:port - разные URL, значит разные выходы.

### Не-стриминговые запросы, таймеры и повторы

Запросы без стриминга идут к апстриму по потоковому эндпоинту и собираются обратно в один JSON-ответ: обычный вызов ждёт ответ целиком и на длинных текстах выходит за любой разумный дедлайн, тогда как поток отдаёт первый токен за секунды. У каждой попытки свой бюджет из `rotation.attemptTimeoutsMs` (в поставляемом конфиге 90, 90, 60, 60, 45, 45, 45 секунд, последнее значение повторяется), поэтому зависший аккаунт пропускается, а не держит клиента. Клиент может задать свою лестницу заголовком `x-attempt-timeouts-ms` (например, `45000,30000`) на не-стриминговых запросах.

Два таймера режут попытку, которая держит сокет без прогресса: `rotation.firstMeaningfulFrameTimeoutMs` (45 с) ждёт первый содержательный кадр с начала попытки, `rotation.idleTimeoutMs` (30 с) ограничивает паузу между кадрами. После того как клиентский поток начался, срез завершает этот поток ошибкой и не подмешивает вывод другого аккаунта.

## Отказы, квоты и TOS

Политика читает только структурированные поля: HTTP-статус, `error.status` и `error.details[]`. Свободный текст сообщения не читается никогда.

| Наблюдение | Что делает запрос | Общее состояние |
|---|---|---|
| отмена клиента или общий дедлайн | остановка, новой работы нет | нет |
| невалидный запрос или локальный дефект парсера | остановка с явной причиной | нет |
| отказ модели или документированный терминал (`STOP`, `MAX_TOKENS`, safety) | возвращает как есть | нет |
| обрезанный/битый/неизвестный терминал, 5xx, сеть | ограниченный alternate | нет |
| голый 429 без деталей | alternate внутри запроса | нет: владелец квоты неизвестен |
| `details[].reason` = `QUOTA_EXHAUSTED` / `DAILY_LIMIT_EXCEEDED` / `INSUFFICIENT_*` или `@type` = `*QuotaFailure`, плюс `quotaResetTime`/`retryDelay` | alternate | аккаунт+модель паркуется до сброса; без подсказки - `rotation.quotaCooldownMs` (5 минут) |
| 403 + `details[].reason` = `TOS_VIOLATION` / `UNSUPPORTED_CLIENT` / `POLICY_VIOLATION` или `metadata.appeal_url` | alternate на следующий аккаунт | аккаунт заблокирован до действия оператора; `rotation.tosPauseMs` > 0 добавляет паузу провайдера |
| прочие 403 / `PERMISSION_DENIED` | `permission_denied`, только этот запрос | нет |
| точный `invalid_grant` на token endpoint | alternate | блокируется поколение credential |
| сбой egress dial/CONNECT | alternate на другой закреплённый выход | только этот egress |

`RATE_LIMIT_EXCEEDED` - транзиентный лимит, а не исчерпанная квота: он остаётся внутри запроса. TOS-блок не имеет таймера и снимается только оператором. Scoped-состояние (парковки квот, TOS-блоки, блоки credential) пишется в `state.poolPath` (по умолчанию `~/.antigravity-proxy/pool-state.json`, режим 0600) и восстанавливается при старте; истёкшие парковки отбрасываются при загрузке. Снять блоки:

```bash
node src/cli.js --clear-pool   # удаляет сохранённое состояние, затем запустите сервис снова
```

## Структура

```
src/
  config/         дефолты, env-оверрайды, лоадер
  credentials/    поиск токен-файлов (agy / gemini-cli / raw), oauth refresh
  rewrite/        openai <-> cloud code трансформы, каталог моделей, identity scrub
  upstream/       клиент cloud code, структурные отказы/политика, scoped-пул
  server/         http: /health, /v1/models, /v1/quota, /v1/chat/completions,
                  /v1beta/models/{model}:{generateContent,streamGenerateContent}
test/             261 тест, без сети (один локальный cert fixture)
```

## Безопасность

- Оставляйте привязку только к `localhost`, если нет осознанной необходимости открывать доступ наружу.
- Никогда не коммитьте файлы токенов и `config.json`.
- Задайте `apiKey` в `config.json`, если к порту возможен доступ из локальной сети.
